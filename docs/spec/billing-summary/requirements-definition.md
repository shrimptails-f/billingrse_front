# 請求集計画面 要件定義

## 1. 画面情報

- 画面名: 請求集計画面
- feature 名: `billing`
- route: `/billing-summary`
- 関連画面: `/dashboard`, `/manual-mail-workflows`, `/login`
- 作成日: 2026-03-29
- 更新日: 2026-03-29

## 2. 目的とスコープ

### 2-1. 目的

- 認証済みユーザーが直近 12 ヶ月の請求推移を確認できるようにする
- 任意の月を選択して、支払先別の請求内訳と件数を把握できるようにする
- 請求処理結果を一覧ではなく集計ビューとして俯瞰し、月ごとの増減や主要支払先を判断する入口にする

### 2-2. スコープ

- この画面で提供する機能:
  - 通貨別の月次請求推移表示
  - バックエンドが返す既定選択月の初期選択
  - 月別棒グラフによる対象月の切り替え
  - 選択月の合計金額、請求件数、補完件数の表示
  - 選択月の支払先別請求総額の表示
  - 初期取得、詳細取得それぞれの loading / error / empty 表示
  - `401` 発生時のログイン画面への復帰
- この画面では扱わない機能:
  - 請求データの編集、削除
  - CSV / Excel エクスポート
  - 任意期間フィルタ、検索、ソート
  - 支払先の詳細画面遷移
  - 通貨の追加登録や為替換算

## 3. 対象ユーザーと利用条件

- 想定ユーザー:
  - ログイン済みの一般ユーザー
  - 月次請求の傾向や支払先の偏りを確認したい運用担当者
- 認証要件:
  - `AuthGuard` 配下の保護画面として利用する
  - 未認証ユーザーは直接利用できない
- 到達経路:
  - `/dashboard` の導線から遷移
  - URL 直接入力
  - ログイン完了後の保護画面遷移

## 4. 前提条件と依存

- 関連 feature:
  - `billing`
  - `auth`
  - `dashboard`
- 関連 API:
  - `GET /billings/summary/monthly-trend`
  - `GET /billings/summary/monthly-detail/:yearMonth`
  - `GET /auth/check`（guard で利用）
- 前提データ:
  - 月別推移 API が既定選択月と 12 ヶ月分の集計を返す
  - 月別詳細 API が支払先上位件数と `その他` を含む内訳を返す
  - 通貨は現時点で `JPY`, `USD` を前提とする
- 外部サービス依存:
  - なし
- レイアウト制約:
  - `DashboardLayout` 配下で表示する
  - グローバルヘッダーとフッターは layout が提供する
  - モバイル優先、白ベース + 緑アクセントを維持する

## 5. ユーザーストーリー

- ユーザーとして、最近の請求総額の推移を確認するために、月別の集計を一覧で見たい
- ユーザーとして、特定の月の支払先別内訳を確認するために、月を選択して内訳を切り替えたい
- ユーザーとして、件数だけでなく補完判定の件数も確認し、月次集計の前提を理解したい
- ユーザーとして、通信失敗時でも再読み込みし、認証切れ時はログインへ戻りたい

## 6. 画面概要

### 6-1. 画面構成

- ヘッダー:
  - `DashboardLayout` のグローバルヘッダー
  - 画面内ヘッダーとしてタイトル、説明文、通貨タブを表示する
- メインコンテンツ:
  - 月別請求総額セクション
  - 支払先別請求総額セクション
- 補助領域:
  - 初期 loading パネル
  - エラーパネル
  - 補完件数の説明 tooltip
- フッター:
  - `DashboardLayout` のグローバルフッター
- モーダル / ドロワー:
  - なし

### 6-2. 主要アクション

- 初期表示時に行うこと:
  - 既定通貨 `JPY` で月別推移を取得する
  - 取得結果の `default_selected_month` をもとに詳細取得対象月を決定する
  - 選択月が存在する場合のみ月別詳細を取得する
- ユーザー操作:
  - 通貨タブの切り替え
  - 月別棒グラフの選択
  - エラーパネルからの再読み込み
  - 補完件数 tooltip の開閉
- 操作結果:
  - 通貨変更時は対象通貨の集計に切り替わり、月選択は既定値へ戻る
  - 月選択時は選択月の支払先別内訳に切り替わる
  - エラー時は再試行を受け付ける
  - 認証切れ時はログイン画面へ遷移する

## 7. ユーザーフロー

1. ユーザーが `/billing-summary` に到達する
2. `AuthGuard` が認証状態を確認する
3. 認証済みであれば、画面は `JPY` の月別推移を取得する
4. 推移取得成功後、既定選択月をもとに支払先別内訳を取得する
5. ユーザーは通貨タブまたは月別棒グラフを操作して表示内容を切り替える
6. 取得成功時は集計値と支払先内訳を更新する
7. 取得失敗時は該当セクションにエラーを表示し、再試行を受け付ける
8. `401` が発生した場合は認証情報を破棄し、`/login` へ戻る

## 8. 機能要件

### 8-1. 初期表示

- 初期表示時に必要な API / データ取得:
  - `GET /billings/summary/monthly-trend?currency=JPY`
  - `default_selected_month` が存在する場合は `GET /billings/summary/monthly-detail/:yearMonth?currency=JPY`
- 初期表示時の UI:
  - タイトル `請求集計`
  - 説明文 `直近12ヶ月の推移と、選択月の支払先別内訳を確認できます。`
  - 通貨タブ `JPY`, `USD`
  - 月別棒グラフ
  - 選択月の合計金額、請求件数、補完件数
  - 支払先別内訳カード
- 権限不足 / 未認証時の扱い:
  - route 到達前は `AuthGuard` で `/login` へ遷移する
  - 画面表示後に API が `401` を返した場合も `/login` へ戻す

### 8-2. 入力 / 操作

- 入力項目:
  - フォーム入力は持たない
  - 操作入力として通貨タブと月選択ボタンを持つ
- 操作可能なボタン / リンク:
  - `JPY` タブ
  - `USD` タブ
  - 各月の棒グラフボタン
  - `再読み込み`
  - `補完件数の説明を表示`
- 活性 / 非活性条件:
  - 通貨タブと月選択は常時操作可能
  - 初期 loading 中もヘッダーは表示する
  - エラーパネル表示時は再読み込み操作を許容する
- 二重送信防止:
  - mutation は存在しない
  - query は TanStack Query により同一 key の重複取得を抑制する

### 8-3. 出力 / 表示

- 月別推移:
  - 12 ヶ月分の棒グラフを横並びで表示する
  - 選択中の月は強調色で表示する
  - 月ラベルは `4月` のような短縮表記にする
- 選択月サマリー:
  - `YYYY年M月`
  - 合計金額
  - 請求件数
  - 補完件数
- 支払先別内訳:
  - 支払先名
  - 合計金額
  - 請求件数
  - `is_other=true` の場合は `集約` バッジを表示する
- 補助文言:
  - 月別推移下に月選択の説明文を表示する
  - 内訳セクションに `上位N件 + その他 / 合計金額が高い順` を表示する
- 表示形式:
  - `JPY` は `ja-JP` の通貨表記
  - `USD` は `en-US` の通貨表記
  - 件数は千区切り付き整数表示
  - `window_start_month`, `window_end_month` は現行 UI では表示しない

## 9. 状態要件

- Loading:
  - 月別推移の初回取得中は loading パネルを表示する
  - 詳細取得中は詳細セクション内に loading 表示を出す
- Empty:
  - 月別推移 `items` が 0 件の場合は `表示できる月別集計データがありません` を表示する
  - 月別詳細 `vendor_items` が 0 件の場合は `選択した月の請求はありません` を表示する
  - 月が選択できない場合は詳細取得を行わない
- Success:
  - 月別推移、詳細、通貨タブを表示する
  - 成功メッセージは不要
- Validation Error:
  - フォーム入力がないため該当なし
- API Error:
  - 月別推移失敗時は画面本文上部にエラーパネルを表示する
  - 月別詳細失敗時は詳細セクション内にエラーパネルを表示する
  - 再試行ボタンから該当 query を再取得できる
- Unauthorized:
  - `401` 時は認証トークンと認証 session query を破棄する
  - `/login` へ遷移する

## 10. バリデーションと業務ルール

- 必須項目:
  - なし
- フォーマット制約:
  - 通貨は `JPY`, `USD` のいずれかのみ
  - 月選択は月別推移 `items` に存在する `year_month` のみ採用する
- 相関チェック:
  - 通貨切替時は選択月 override をリセットし、切替後データの既定月を採用する
- 業務上の入力制約:
  - 補完件数は `請求日がメールに無いため、メール受信日で判定した件数` として扱う
  - 支払先別内訳は API が返す `vendor_limit` 件 + `その他` を前提とする
- 操作可能条件:
  - 選択月が決定できない場合、詳細 query は実行しない

## 11. API / データ要件

### 11-1. 利用 API 一覧

| 用途           | Method | Endpoint                                      | 入力                                 | 出力                                                                                                                  | 備考                                     |
| -------------- | ------ | --------------------------------------------- | ------------------------------------ | --------------------------------------------------------------------------------------------------------------------- | ---------------------------------------- |
| 月別推移取得   | GET    | `/billings/summary/monthly-trend`             | `currency`, `window_end_month?`      | `currency`, `window_start_month`, `window_end_month`, `default_selected_month`, `items[]`                             | 画面では `window_end_month` を指定しない |
| 選択月詳細取得 | GET    | `/billings/summary/monthly-detail/:yearMonth` | path: `yearMonth`, query: `currency` | `year_month`, `currency`, `total_amount`, `billing_count`, `fallback_billing_count`, `vendor_limit`, `vendor_items[]` | 月選択時に利用                           |
| 認証確認       | GET    | `/auth/check`                                 | なし                                 | なし                                                                                                                  | route guard で利用                       |

### 11-2. データ要件

- 画面表示に必要なデータ項目:
  - 通貨
  - 既定選択月
  - 月別総額、件数、補完件数
  - 支払先名、支払先別総額、件数、その他フラグ
- フロントで加工が必要な項目:
  - `default_selected_month` と `selectedMonthOverride` を組み合わせて現在選択月を決定する
  - 月別最大値、支払先別最大値からバー高さ / 幅を算出する
  - 年月、金額、件数を表示用に整形する
- 欠損時のフォールバック方針:
  - override 月が現行データに存在しない場合は `default_selected_month` に戻す
  - 詳細未取得時のサマリーは月別推移の選択中 item を優先表示する
  - 詳細が未取得なら支払先別一覧は描画しない

## 12. UI / UX 要件

- モバイル優先で成立すること
- 12 ヶ月分の棒グラフは狭い画面では横スクロール可能にすること
- 通貨切替と月選択の状態が視覚的に分かること
- 主要情報である合計金額、請求件数、補完件数をファーストビュー内で把握しやすくすること
- エラー表示は該当セクションの近くに出し、画面全体の文脈を失わせないこと
- 期間ラベルや判定ルールの長文は常時表示せず、必要最低限の補助文言に留めること

## 13. アクセシビリティ要件

- 通貨切替は `tablist` / `tab` を用いて実装する
- 月選択は各ボタンに `YYYY年M月を選択` の名前を持たせる
- 選択中状態は `aria-selected` または `aria-pressed` で伝える
- エラーパネルは `role="alert"` を持たせる
- tooltip は `role="tooltip"` と `aria-describedby` で関連付ける
- キーボードだけで通貨切替、月選択、再試行、tooltip 開閉を完結できる
- コントラストは WCAG AA を満たす

## 14. 非機能要件

- 想定表示件数:
  - 月別推移は最大 12 件
  - 支払先別内訳は `vendor_limit + その他` 程度
- パフォーマンス上の注意:
  - サーバ状態をローカル state に二重保持しない
  - 通貨変更時は必要な query のみ切り替える
  - グラフ描画は軽量な DOM のみで構成する
- 監視 / ログ出力の要件:
  - 認証トークンや機微情報をログ出力しない
  - エラーは既存 API クライアントの整形メッセージを利用する
- セキュリティ上の注意:
  - 保護画面として認証前提で扱う
  - `401` 後は認証情報を破棄してログインへ戻す
  - 画面から直接 `fetch` を呼ばず API モジュール経由で通信する

## 15. 対象外

- 期間絞り込み UI
- 通貨の追加設定
- 詳細画面へのドリルダウン
- 請求元メールや個票の閲覧
- 集計結果のダウンロード

## 16. Definition of Done

- 認証済みユーザーが `/billing-summary` を表示できる
- `JPY` 初期表示で月別推移と既定月内訳が確認できる
- 通貨切替と月選択で表示内容が更新される
- Loading / Empty / Error / Unauthorized の状態が定義されている
- API 契約と表示項目の対応が明確である
- テスト観点が洗い出されている
