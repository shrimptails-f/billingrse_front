# メールアカウント連携画面 要件定義

## 1. 画面情報

- 画面名: メールアカウント連携画面
- feature 名: `mail-account-connections`
- route: `/mail-account-connections/gmail`
- 関連画面:
  - `/dashboard`
  - `/manual-mail-workflows`
  - `/mail-account-connections/gmail/callback`
- 作成日: 2026-03-29
- 更新日: 2026-03-29

## 2. 目的とスコープ

### 2-1. 目的

- 認証済みユーザーが Gmail アカウントを業務利用向けに連携し、後続の手動メール取得機能で利用できる状態にする
- 連携済みアカウントの一覧確認と解除を 1 画面で完結させ、メール連携の管理入口にする

### 2-2. スコープ

- この画面で提供する機能:
  - 連携済みメールアカウント一覧の取得と表示
  - Gmail OAuth 開始 API の実行
  - Google 認可画面への遷移
  - 連携済みアカウントの解除
  - ホームへの戻り導線
  - 関連画面である OAuth コールバック画面への遷移前提整理
- この画面では扱わない機能:
  - Gmail 以外のメールプロバイダ連携
  - 連携済みアカウントの編集、メモ付与、並び替え、検索
  - 複数アカウント一括解除
  - OAuth コールバック完了後の詳細監査ログ表示

## 3. 対象ユーザーと利用条件

- 想定ユーザー:
  - 既にログイン済みの一般ユーザー
  - 手動メール取得の事前準備としてメール連携を追加したいユーザー
- 認証要件:
  - `AuthGuard` 配下でのみ利用できる
  - 未認証ユーザーは本画面へ直接到達できない
- 到達経路:
  - ヘッダーメニューの `メールサービス連携`
  - 手動メール取得画面の「先に Gmail 連携を追加してください」導線
  - URL 直接入力

## 4. 前提条件と依存

- 関連 feature:
  - `mail-account-connections`
  - `manual-mail-workflows`
  - `dashboard`
  - `auth`
- 関連 API:
  - `GET /mail-account-connections`
  - `POST /mail-account-connections/gmail/authorize`
  - `DELETE /mail-account-connections/{connectionId}`
  - `POST /mail-account-connections/gmail/callback`（関連画面で利用）
- 前提データ:
  - 連携一覧は `id`, `provider`, `account_identifier`, `created_at`, `updated_at` を返す
  - OAuth 開始 API は `authorization_url`, `expires_at` を返す
  - OAuth コールバック完了 API は `message` を返す
- 外部サービス依存:
  - Google OAuth 認可画面
- レイアウト制約:
  - `DashboardLayout` 配下で表示する
  - モバイル優先の 1 カラム構成を基本とする
  - 白ベース、緑アクセント、中央寄せカードを使う

## 5. ユーザーストーリー

- ユーザーとして、手動メール取得を使うために Gmail アカウントを連携したい
- ユーザーとして、現在どのメールアカウントが連携済みかを画面上で把握したい
- ユーザーとして、不要になった連携を誤操作なく解除したい
- ユーザーとして、Google 認可失敗や API エラーが起きたときに、次に取るべき行動を理解したい

## 6. 画面概要

### 6-1. 画面構成

- ヘッダー:
  - `DashboardLayout` の `AppHeader` を利用する
- メインコンテンツ:
  - 画面タイトル
  - 補助説明文
  - `連携追加` ボタン
  - 画面全体のエラーアラート
  - 連携済みアカウント一覧
  - `ホームへ戻る` ボタン
- 補助領域:
  - `DashboardLayout` が提供する背景グラデーションと `.page-shell`
- フッター:
  - `DashboardLayout` の `AppFooter`
- モーダル / ドロワー:
  - カスタムモーダルは使わない
  - 解除確認はネイティブの確認ダイアログを使う

### 6-2. 主要アクション

- 初期表示時に行うこと:
  - 連携済みアカウント一覧を取得する
- ユーザー操作:
  - `連携追加` で Gmail OAuth 開始を要求する
  - 一覧行の `解除` で対象アカウントの連携を解除する
  - `ホームへ戻る` で `/dashboard` へ遷移する
- 操作結果:
  - OAuth 開始成功時は Google 認可画面へ遷移する
  - 解除成功時は一覧を再取得して反映する
  - 失敗時は画面内にエラーを表示する

## 7. ユーザーフロー

1. ユーザーが `/mail-account-connections/gmail` に到達する
2. 画面はタイトル、説明文、`連携追加` ボタン、連携一覧を表示する
3. 初期表示で `GET /mail-account-connections` を実行する
4. ユーザーが `連携追加` を押すと `POST /mail-account-connections/gmail/authorize` を実行する
5. 成功時は `authorization_url` に遷移し、Google 認可を行う
6. Google から `/mail-account-connections/gmail/callback` に戻り、関連画面でコールバック完了 API を実行する
7. ユーザーが連携ページへ戻ると、最新の連携一覧を確認できる
8. ユーザーは任意の連携に対して `解除` を実行できる

## 8. 機能要件

### 8-1. 初期表示

- 初期表示時に必要な API / データ取得:
  - `GET /mail-account-connections`
- 初期表示時の UI:
  - アイブロウ `メールサービス連携`
  - タイトル `Gmail アカウント連携`
  - 説明文 `Gmail アカウントを連携して、このアプリで利用するメール送受信の入口を管理します。`
  - `連携追加`
  - `連携済みアカウント` 見出し
  - `ホームへ戻る`
- 権限不足 / 未認証時の扱い:
  - route guard により未認証ユーザーは `/login` へ遷移する
  - 認証リフレッシュ後も `401` が残る場合は、画面内メッセージで再ログインを促す

### 8-2. 入力 / 操作

- 入力項目:
  - なし
- 操作可能なボタン / リンク:
  - `連携追加`
  - 各連携行の `解除`
  - `ホームへ戻る`
- 活性 / 非活性条件:
  - `連携追加` 実行中は `連携追加` と `ホームへ戻る` を非活性にする
  - 解除中は対象行の `解除` のみ非活性にする
- 二重送信防止:
  - OAuth 開始 mutation 実行中は再クリック不可にする
  - 解除中の行は `解除中...` を表示し、同一行の再操作を防ぐ
  - 解除前に確認ダイアログを表示する

### 8-3. 出力 / 表示

- 一覧表示内容:
  - プロバイダアイコン
  - `account_identifier`
  - `解除` アクション
- ラベルや補助文言:
  - 空状態: `連携済みのアカウントはありません`
  - 一覧取得失敗: `連携情報の取得に失敗しました。時間をおいて再度お試しください。`
  - OAuth 開始失敗:
    - `401`: `認証エラーが発生しました。再度ログインしてください。`
    - その他: `Gmail 連携の開始に失敗しました。時間をおいて再度お試しください。`
  - 解除失敗:
    - `401`: `ログイン期限が切れました。再度ログインしてください。`
    - `404`: `対象の連携が見つかりませんでした。`
    - その他: `連携の解除に失敗しました。時間をおいて再度お試しください。`
- 日付、通貨、件数などの表示形式:
  - 本画面では日付や件数は表示しない

## 9. 状態要件

- Loading:
  - 初期一覧取得中はスピナーを表示する
  - OAuth 開始中は `連携追加` をローディング表示にする
  - 解除中は対象行の `解除` を `解除中...` にする
- Empty:
  - `items.length === 0` の場合に空文言を表示する
  - 次に促すアクションとして `連携追加` を維持する
- Success:
  - OAuth 開始成功時は画面内で成功表示せず外部画面へ遷移する
  - 解除成功時はトーストを出さず一覧更新のみ行う
  - コールバック成功時は関連画面で成功メッセージを表示する
- Validation Error:
  - 入力フォームを持たないため該当なし
- API Error:
  - 失敗箇所ごとに該当セクション直近へアラートを表示する
  - OAuth 開始失敗時は再度 `連携追加` できる
  - 一覧取得失敗時は画面再訪または再読み込みで回復を試みる
- Unauthorized:
  - `AuthGuard` で未認証は事前に弾く
  - 保護画面内の API がリフレッシュ後も `401` を返した場合は、画面内で再ログインを促す
  - `/login` へ即時リダイレクトするかは未解決事項で管理する

## 10. バリデーションと業務ルール

- 必須項目:
  - なし
- フォーマット制約:
  - なし
- 相関チェック:
  - なし
- 業務上の入力制約:
  - 連携対象プロバイダは現時点で Gmail のみ
  - 同一 Gmail アカウントの重複連携可否はバックエンド判定に従う

## 11. API / データ要件

### 11-1. 利用 API 一覧

| 用途         | Method | Endpoint                                    | 入力            | 出力                              | 備考               |
| ------------ | ------ | ------------------------------------------- | --------------- | --------------------------------- | ------------------ |
| 連携一覧取得 | GET    | `/mail-account-connections`                 | なし            | `items`                           | 初期表示で利用     |
| OAuth 開始   | POST   | `/mail-account-connections/gmail/authorize` | なし            | `authorization_url`, `expires_at` | 成功時に外部遷移   |
| 連携解除     | DELETE | `/mail-account-connections/{connectionId}`  | path parameter  | なし                              | 成功後に一覧再取得 |
| OAuth 完了   | POST   | `/mail-account-connections/gmail/callback`  | `code`, `state` | `message`                         | 関連画面で利用     |

### 11-2. データ要件

- 画面表示に必要なデータ項目:
  - `id`
  - `provider`
  - `account_identifier`
- フロントで加工が必要な項目:
  - `provider` は小文字化してアイコン種別へ変換する
  - OAuth コールバック画面では `code`, `state`, `error` クエリを状態に変換する
- 欠損時のフォールバック方針:
  - `authorization_url` が空または欠損ならエラーとして扱う
  - 未知の `provider` はフォールバックアイコンを表示する

## 12. UI / UX 要件

- モバイル優先で成立すること
- 600px 未満では 1 カラム、カード幅は全幅、左右余白は layout に委譲する
- 600px 以上ではカード幅を広げても 1 カラム構成を維持する
- 960px 以上では最大幅を制御し、カードの読みやすさを優先する
- `連携追加` は画面上部に置き、空状態でも見失わないこと
- 一覧が 0 件でも目的が理解できる説明文を維持すること
- 解除操作は誤タップ防止のため確認ダイアログを挟むこと

## 13. アクセシビリティ要件

- 主要ボタンに明確なラベルを付ける
- キーボードだけで `連携追加`、`解除`、`ホームへ戻る` を操作できる
- Loading 中のスピナーは読み上げ可能なラベルを持つ
- エラーメッセージは `role="alert"` または `aria-live="polite"` を利用する
- コールバック結果画面は状態変化を読み上げ可能にする
- コントラストは WCAG AA を満たす

## 14. 非機能要件

- 想定表示件数:
  - 1 ユーザーあたり数件から十数件程度を想定する
- パフォーマンス上の注意:
  - 一覧は TanStack Query のキャッシュを利用する
  - 不要な二重リクエストを避ける
  - コールバック画面では Strict Mode 下でも完了 API を 1 回だけ送る
- 監視 / ログ出力の要件:
  - OAuth `code`, `state`, `authorization_url` を不用意に console 出力しない
  - 連携解除失敗時も機微情報をログへ残しすぎない
- セキュリティ上の注意:
  - 本画面は認証済み route 配下で扱う
  - OAuth コールバック画面では処理後にクエリを URL から除去する
  - 連携解除は対象アカウント識別子を確認してから実行する

## 15. 対象外

- Gmail 以外のプロバイダ追加
- 連携アカウントのラベル付け、検索、ソート
- 連携の一括操作
- 連携履歴や詳細監査ログの表示

## 16. Definition of Done

- 認証済みユーザーが連携一覧を閲覧できる
- `連携追加` から Google 認可フローへ遷移できる
- 連携解除が確認付きで実行できる
- Loading / Empty / Error / Callback 成功失敗を設計済みである
- API 契約と表示項目の対応が明確である
- テスト観点が主要分岐まで洗い出されている
